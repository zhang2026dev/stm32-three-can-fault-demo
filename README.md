# stm32-three-can-fault-demo
基于 FreeRTOS 的三 STM32 CAN 总线串联通信容错系统，实现多芯片数据采集、舵机控制、双分区 Flash 存储、环形缓冲区故障过滤、看门狗复位容错与异常日志持久化。

# 三芯片STM32 CAN总线通信容错系统
## 项目简介
本项目采用 **三块STM32芯片CAN总线串联组网**，分为采集芯片、存储芯片、控制芯片。基于FreeRTOS实时操作系统，实现分布式数据采集、舵机驱动、数据互传、容错处理、日志分级存储、看门狗死机复位恢复的整套嵌入式容错通信系统。

项目解决多机通信丢包、设备超时离线、系统崩溃、Flash频繁擦写寿命损耗等工程问题，具备完整的工业级容错与数据持久化能力。

## 系统架构（三芯片分工）
### 1. 采集芯片
- ADC实时数据采集
- S90舵机角度驱动控制
- 周期性发送设备心跳包
- 接收控制芯片下发角度指令并执行动作

### 2. 存储芯片
- CAN总线接收采集芯片ADC数据
- CAN总线接收控制芯片故障日志数据
- 通过**互斥锁**完成队列接收与底层写入，防止多线程抢占冲突
- Flash分区存储：
  - 分区1：长期保存ADC采集数据
  - 分区2：保存系统异常错误日志
- 将存储数据实时回传给控制芯片用于显示

### 3. 控制芯片（核心容错单元）
- 编码器手动设置舵机角度、按键确认下发控制指令
- LED实时显示ADC数据、舵机角度、系统错误信息
- **8秒心跳超时检测机制**
- **环形缓冲区故障过滤机制**（保护Flash寿命）
  - 普通超时故障：累计3条再写入Flash
  - 系统致命故障：直接落盘，无需等待
- 本地Flash独立存储故障日志
- 12秒看门狗超时复位机制
- 设备重启后自动读取历史故障日志并上传存储芯片归档

## 核心数据流
1. 采集芯片：采集数据 + 心跳上报 → CAN总线
2. 存储芯片：互斥锁队列接收 → 双Flash分区存储 → 回传控制芯片显示
3. 控制芯片：人机交互下发指令 + 实时数据显示
4. 容错流程：超时检测 → 环形缓冲区缓存 → 分级存储 → 本地备份 → 全网同步
5. 死机恢复：看门狗复位 → 读取历史日志 → 重新同步数据

## 技术栈
- 主控：STM32
- 系统：FreeRTOS（消息队列、互斥锁、任务管理）
- 通信：CAN总线多机串联通信
- 存储：Flash分区存储、数据持久化
- 容错：心跳检测、超时判断、环形缓冲区、看门狗复位
- 外设：ADC采集、S90舵机、编码器、LED
